Şablonlar

Bu şablonlar yeni başlayan və orta səviyyəli IT Biznes Analitiklər üçün hazırlanıb. Tələblərin sənədləşdirilməsi, user story və use case-lərin yazılması, stakeholder və proses analizi, texniki analiz və dəyişikliklərin strukturlaşdırılması üçün hazır forma kimi istifadə edilə bilər.

← Ana səhifə

Şablon səviyyələri: Başlanğıc – yeni başlayanlar üçün sadə şablon; Orta – daha detallı analiz tələb edən şablon; Praktiki – real layihələrdə istifadə üçün genişləndirilmiş şablon.

Bu kateqoriyada şablon tapılmadı.

User Story Şablonu

Başlanğıc

İstifadəçi ehtiyacını qısa və aydın formada ifadə etmək üçün.

Nə vaxt: Backlog-a yeni tələb əlavə edəndə və ya sprint planlaşdırmasında.

Şablona bax ▾

Məqsəd

Bu şablon istifadəçi ehtiyacını qısa və aydın formada ifadə etmək üçün istifadə olunur.

Əsas bölmələr

  • User story (rol – məqsəd – fayda)
  • Acceptance criteria
  • Biznes qaydaları və qeydlər

Hazır şablon

User Story:
Bir [rol] olaraq,
Mən [məqsəd / ehtiyac] istəyirəm,
Beləliklə [biznes dəyəri / nəticə] əldə edim.

Acceptance Criteria:
1. GIVEN ...
   WHEN ...
   THEN ...

2. GIVEN ...
   WHEN ...
   THEN ...

Business Rules:
- ...

Notes:
- ...

Nümunə

Bir müştəri olaraq, Mən şəxsi kabinetdə aktiv sığorta müqavilələrimi görmək istəyirəm, Beləliklə müqavilə məlumatlarımı filial ilə əlaqə saxlamadan yoxlaya bilim. Acceptance Criteria: GIVEN müştərinin aktiv müqaviləsi var WHEN müştəri şəxsi kabinetə daxil olur THEN sistem aktiv müqavilələri siyahıda göstərir.

Acceptance Criteria (Qəbul meyarları)

Başlanğıc

User story-nin «tamamlandı» sayılması üçün lazım olan konkret şərtlər.

Nə vaxt: Hər user story üçün — developer və tester eyni nəticəni gözləsin deyə.

Şablona bax ▾

Məqsəd

Funksiyanın hansı şərtlərdə düzgün sayılacağını dəqiqləşdirmək. İki üsul var: Gherkin (Given/When/Then) və ya sadə siyahı.

Əsas bölmələr

  • Hər meyar üçün şərt, hərəkət və nəticə
  • Müsbət və mənfi (xəta) halları

Hazır şablon

ACCEPTANCE CRITERIA

User Story / Funksiya:

Üsul 1 — Gherkin (Given/When/Then):
AC-01:
  GIVEN [ilkin vəziyyət]
  WHEN  [istifadəçi hərəkəti]
  THEN  [gözlənilən nəticə]

AC-02 (mənfi hal):
  GIVEN ...
  WHEN  ...
  THEN  [xəta mesajı / blok]

Üsul 2 — Sadə siyahı (checklist):
- [ ] Şərt 1
- [ ] Şərt 2
- [ ] Xəta halı düzgün idarə olunur

Nümunə

AC-01: GIVEN istifadəçi düzgün email və şifrə daxil edib WHEN «Daxil ol» düyməsini basır THEN sistem onu şəxsi kabinetə yönləndirir. AC-02: GIVEN şifrə yanlışdır WHEN istifadəçi daxil olmağa çalışır THEN «Email və ya şifrə yanlışdır» mesajı görünür.

Stakeholder Interview Questions

Başlanğıc

Maraqlı tərəflərdən tələbləri toplamaq üçün hazır sual dəsti.

Nə vaxt: Tələblərin toplanması (elicitation) mərhələsində müsahibə apararkən.

Şablona bax ▾

Məqsəd

Stakeholderdən düzgün sualları soruşaraq real ehtiyacı, problemi və gözləntini üzə çıxarmaq.

Əsas bölmələr

  • Kontekst və rol sualları
  • Problem və ehtiyac sualları
  • Proses, gözlənti və prioritet sualları

Hazır şablon

STAKEHOLDER MÜSAHİBƏ SUALLARI

Rol və kontekst:
   - Bu prosesdə sizin rolunuz nədir?
   - Gündəlik işinizdə bu sistemdən necə istifadə edirsiniz?

Hazırkı vəziyyət (As-Is):
   - İndi bu iş necə görülür?
   - Hansı addımlar vaxt aparır və ya çətindir?

Problem və ehtiyac:
   - Ən böyük problem nədir?
   - Bu problem işə necə təsir edir?

Gözləntilər (To-Be):
   - İdeal həll necə görünərdi?
   - Hansı nəticə sizin üçün uğur sayılır?

Prioritet və məhdudiyyət:
   - Ən vacib funksiya hansıdır?
   - Hər hansı məhdudiyyət və ya qayda varmı?

Yekun:
   - Əlavə etmək istədiyiniz nə var?
   - Bu mövzuda daha kimlə danışmalıyam?

Nümunə

Sual: «İndi müştəri müqaviləsini necə öyrənir?» Cavab: «Filiala zəng edir.» → Buradan «onlayn müqavilə görünüşü» ehtiyacı üzə çıxır.
